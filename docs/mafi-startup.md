## 模型：DeepSeek 主用，MiniMax 可切换与评测

已按你的新决定取消 Grok API 方案，改用已有余额的两个服务。本机处理步骤初始使用 DeepSeek，MiniMax 作为可手动选择和对照评测的模型；未配置自动故障切换，也未因为添加 MiniMax 而同时发送两份请求。具体步骤分工待同一批真实样本验证后再定，不预先承诺谁的精选更准。

| 用途 | 配置 | 密钥位置 |
|---|---|---|
| 默认主用 | https://api.deepseek.com/v1；deepseek-flash；关闭思考，开启 JSON 模式 | .env 的 LLM_API_KEY |
| 可选 MiniMax | https://api.minimax.io/v1；MiniMax-M3；预设名 minimax-m3 | .env 的 MINIMAX_API_KEY |

两家均使用框架现有的 OpenAI 兼容 Chat Completions 接口，不新增 SDK 或模型调用路径。[DeepSeek 接入说明](https://api-docs.deepseek.com/zh-cn/)、[MiniMax 国际平台接入说明](https://platform.minimax.io/docs/api-reference/text-openai-api)。MiniMax-M3 支持关闭思考；当前预设采用此模式并将思考内容与答案分开。未直接换成始终思考的 MiniMax-M3.1-Flash，以免照搬短任务的输出额度导致空答案。

MiniMax 官方当前参数表未列出 response_format，因此预设不发送此字段，依靠提示词请求 JSON，框架仍校验并拒绝不合格式的输出；这不代表服务端保证 JSON 或已经实测成功。DeepSeek 的 JSON 模式按官方说明使用，仍需关注空 content、截断和实际成功率。[MiniMax 参数表](https://platform.minimax.io/docs/api-reference/text-chat-openai)、[DeepSeek JSON 模式](https://api-docs.deepseek.com/zh-cn/guides/json_mode/)。

本次已生成本机 .env，用户已在本机填写密钥；模板密钥继续留空，自动采集和模型处理开关保持关闭。已按约执行每家一次的最小合成连通性请求，具体账号状态和结果只存本机 .data/live-connectivity-report.md，不放入源码包；.env 也不进入 Git 或交付包。在本机填入两个平台的普通 API key，确认用量限制后再小批验证。不要在聊天、截图或源码中发送 key，也不要填网页登录 cookie。MiniMax 使用国际平台的密钥与 api.minimax.io 配套，不与国内平台混用，也不把订阅专用 key 当普通余额 API key。现有 .env 不会被新模板覆盖；若以前填过 Grok，需要自行替换 LLM_* 并清除旧服务参数，后台已保存的逐步模型设置也需核对。

只填 MINIMAX_API_KEY 不会自动改选模型。在后台“模型与评测”可按步骤选 minimax-m3，或在费用许可后用 eval-selection 的 --models default,minimax-m3 对照；该命令比较评分模型，预筛仍沿用当前步骤设置。模型切换只影响后续任务。

## 域名、部署与条款：现在可以暂不处理什么

“本机运行”就是程序和数据库放在这台电脑，使用 http://localhost:3000；电脑或程序关闭后就不能继续更新。仅此阶段无需公网域名、云主机、CDN或公开联系方式，不会替你购买或注册。

新 .env.example 已把 Docker 的 PORT 设成 127.0.0.1:3000。已有 .env 需自行补上同一设置并重启，再核对实际端口映射只在 127.0.0.1；只写 SITE_URL=localhost 并不限制监听。直接运行 Node 时按部署说明分别确认 API_HOST、WEB_HOST 只监听 127.0.0.1；当前预览已显式如此设置。

以后若想手机随时访问或让别人使用，再决定一台常开主机、访问方式与使用人群；公网服务再配域名、HTTPS、备份、管理员入口保护及适用手续。不能把本机模式直接换成 0.0.0.0 或路由器端口转发来充当私密部署：目前网页、RSS、公开 API 和 MCP 对所有能连到服务的人均为匿名只读公开。

site/pages/terms.md 与 privacy.md 继续标为草案，运营者、邮箱与生效日留待公开提供服务前确认，不伪造公司、地址、备案或保存期限。你届时只需给出运营主体和专用联系邮箱，并确认实际使用的服务与数据保存安排，再形成可审阅的正式版本。本机保存数据不表示模型推理也在本机：启用后，公开资讯与提示词会发送给当前步骤选用的 DeepSeek 或 MiniMax；本新闻站不接入个人持仓、盈亏、账户或身份文件。

具体按这六步：

1. 先准备 **20–30 条**试标：保留原标题、原文链接、发布日、来源、正文/关键段落。只看标题拿不准的，先读原文。表里先不显示模型分数，避免影响判断。
2. 你只填两项：**应选 / 不应选 / 待定**，以及一句理由。判断“是否值得我在日报里看到”，不要代模型打 0–100 分。“待定”用于缺材料或边界未决定，不能硬算正确答案。
3. 根据试标修正文字标准，再扩充到 **100–200 条**。建议约四成器械与上海药政/医保/采购、三成 AI、三成股票/黄金/宏观；这只是采样起点，按真实信息量调整，不是评分权重。补充医药与黄金反例、媒体来源及接近入选的难例，不能只挑好新闻。
4. 总体按事件分开发集约 70% 与留出集约 30%；同一公告的转载、同一事件的几个近似稿放在同一边，减少信息泄漏。首批 30 条已用于讨论偏好，全部属于开发集；第二批在答案填写前冻结为开发 40、留出 30，合计为开发 70、留出 30。008/009/010 及相关工作流保守隔离，分组不等于已经确认事件合并。**每条按单篇价值标注，不因已有另一篇入选就把重复报道判为不应选**；去重另由归组规则处理。
5. 将人工表格转成金标：应选对应 select，不应选对应 reject；缺材料或边界未决定的待定保留 pending，不能自动映射为 either，只有明确“两个决定都可接受”才用 either（不计决定性指标）。仅正文材料确认后的条目进入可评分文件；保留 caseId、来源分级、samplingStratum 与 benchmarkSplit。原文 URL、标注理由、附件和待补项保留在配套表中。**本批转换已完成**，开发金标和封存留出金标分别保存在 .data/annotations-100-20261022/4e71aadb0100/，不要求你手写 JSON。暂缺正文的 4 条仍保留人工判断，不作为 reject 或 either 混入评测。
6. 获得 API key 与费用授权后，先跑开发集评测，核对漏选、误选、覆盖率及完整准确率。先改文字规则，有证据再调数字门槛，最后跑留出集。本次使用 --no-import，结果只写本地文件，没有导入后台 SelectBench；下一步需先统一历史材料的评判时点，再锁定分级候选并验收留出集。新增行业与换模型后同样复核。现在仍保留原有门槛，没有把开发集拟合当作留出集结果。

## 本机自动采集/精选循环（2026-10-23 Asia/Tokyo）

```powershell
cd <repo>
node --env-file=.env scripts/start-mafi-auto.mjs          # 后台：10 分钟采集 / 60 分钟精选
node scripts/stop-mafi-auto.mjs                           # 停止
node --env-file=.env scripts/start-mafi-auto.mjs --once   # 只跑一轮采集+分析后退出
```

- 每 tick analyze 上限约 12 篇 / 80 请求（小时级精选），仍留 hourStop 余量，避免一小时打满 800（live llm/deepseek 现为 20/800/1500；软停约 day-5 / hour-10）。
- 预算触顶则该 tick 停止，下一轮再试；jina 预算保持 0。
- 详情见 [mafi-model-on.md](mafi-model-on.md)。
- 无前端 realtime：刷新页面即可看到 DB 中的新采集/精选结果。
